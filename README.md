эм ну типа
1. Queue работает по принципу похожем на очередь грубо говоря первым пришёл первым и ушёл применяется для организации очередей. Stack точно так же только наоборот последним пришёл первым ушёл и используется для организации стека.
2. AddLast возвращает объект LinkedListNode который даёт доступ к нужному месту списка.
3. При попытке чтения отсутствующего ключа выводит исключение KeyNotFoundException, чтобы этого избежать нужно использовать метод TryGetValue он проверяет наличие ключа  и выводит bool
4. IComparable<T> реализуется внутри самого класса и задает его «естественный» порядок сортировки. IComparer<T> реализуется в отдельном классе и позволяет задавать альтернативные правила сортировки, не меняя исходный класс.Если тип не реализует ни один из интерфейсов, вызов List<T>.Sort() выбросит исключение InvalidOperationException
5. Это означает, что LINQ-запрос не выполняется в момент его объявлеения. Обход коллекции происходит когда результаты запроса по факту запрашиваются.
6. IGrouping — это интерфейс, представляющий группу элементов с общим ключом. Он наследует IEnumerable<TElement>, поэтому к нему применимы все стандартные операции LINQ.
7. Join сопоставляет элементы двух коллекций по заданному ключу, тоесть если у одного клиента несколько заказов, Join создаст несколько строк в результирующей выборке.
8. Итераторы используют ключевое слово yield return, которое приостанавливает выполнение метода после возврата каждого элемента. Take(N) в LINQ знает, что ему нужно получить только первые N элементов.
9. Универсальный интерфейс IEnumerable<T> наследуется от неуниверсального IEnumerable, явная реализация нужна для того, чтобы скрыть неуниверсальный метод от случайного вызова напрямую
10. Индекс самого старого элемента вычисляется по формуле: (next - size + capacity) % capacity, где next — индекс для следующей записи, size — текущее количество элементов в буфере, а capacity — общая ёмкость буфера.
